# ジョハリの窓 — ローカル自己分析

2〜10人が同じWi-Fiで使う、日本語の自己理解ツールです。外部サービスやアカウント登録は不要。React / TypeScript / Vite / Tailwind CSS、Express / Socket.IOを使っています。診断データはメモリ上のみで扱い、PCへの自動保存は行いません。

## 必要な環境

- Windows または macOS
- Node.js **22.13.0以上の22系**（検証環境: 22.20.0）。
- 初回のパッケージ取得にはインターネット接続が必要です。実行中は外部APIを利用しません。

## セットアップ・起動

```sh
git clone https://github.com/Aya-8/JohariWindow.git
cd JohariWindow
npm ci
npm run build
npm start
```

このリポジトリにはアプリのソースコードとテストを保存します。利用時はホストPCでNode.jsサーバーを起動します。診断データ・認証情報・エクスポート・動作確認用ファイルはGitHubへ登録しません。

ホストPCで http://localhost:3000 を開きます。初期状態から一時保存専用です。**Ctrl + Cでサーバーを停止すると、すべての回答・結果・メモが失われます。**サーバーは `0.0.0.0:3000` で待ち受けます。ポート変更は `PORT` 環境変数で指定します。

3000番を別アプリが使用している場合は、WindowsのPowerShellで次のように起動し、http://localhost:3001 を開いてください。

```powershell
$env:PORT='3001'
npm start
```

macOSでは `PORT=3001 npm start` です。変更した番号をファイアウォールでも許可してください。

開発時は `npm start` と別のターミナルで `npm run dev` を実行できます。通常利用・スマートフォンでの検証には、ビルド後の3000番ポートを使ってください。

## 使い方

1. ホストが表示名を入力して作成します。自動生成されるルームコードでセッションを識別します。ホストも参加者に含まれます。
2. ロビーで実際のWi-FiアダプターのIPアドレスを選択します。VPNや仮想アダプターがある場合は選択に注意してください。
3. 友人が同じWi-Fiに接続し、QRコードまたは参加URLをスマートフォンで開き、名前を入力します。ルームコードの手入力でも参加できます。
4. ロビーでホストが特徴の最低選択数・最大選択数を1〜45個から設定します（初期値3〜8個）。同じ数にすると固定個数にできます。「選択数の設定を保存」で全員へ共有し、未保存の変更も開始時に反映します。自己評価・他者評価に共通で、開始後は変更できません。2〜10人の入室後にホストが開始します。開始後は新規入室できません。
5. 各自45種類の特徴からホストが設定した数を選び「次へ」を押します。選んだ特徴ごとに理由・具体的なエピソードを任意で記入し、自己評価を確定します。すべて空欄でも確定できます。全員完了すると他者評価に進みます。特徴は「論理的／直感的」などを並べて表示し、各組の両方を選ぶことも、どちらも選ばないこともできます。全45項目を最初から表示します。理由の画面には、就活の自己分析に向けて「場面・行動・結果／学び」を振り返るヒントと記入例を用意しています。他者評価では実際に見た行動と周囲への影響を思い出せる案内に切り替わります。記入例は説明用で、回答欄へ自動入力されません。
6. 自分以外の全員についても「特徴を選ぶ → 次へ → 理由・エピソードを任意で記入」の順に進めます。以前からの5つの自由記述質問は「全体的なフィードバック」内にあります。特徴の選択に戻って修正でき、下書き保存・復元も可能です。他者評価は下書きとして保存され、全員分を記入した後に「回答を確定する」でまとめて確定します。確定前は保存済みの回答も修正できます。確定後は変更できません。
7. 全員完了すると回答完了待機になります。ホストが公開ボタンを押すと全員に一斉公開します。各自が見られるのは本人の結果だけです。
8. 振り返りを記入して「メモを保存」（この回のメモリ内だけに反映）。JSON・CSVのダウンロード、ブラウザ印刷から「PDFとして保存」が利用できます。エクスポートと印刷には編集中のメモも含まれます。手動で保存したJSON・CSV・PDFは端末に残るため、記録を残したいときだけ利用してください。

自己評価・他者評価は入力後約0.5秒でサーバーのメモリへ下書きを自動保存します。最低選択数に達していなくても0個から設定上限まで保存し、別の人への切り替えや「入り口へ」では保存の完了を待ちます。確定にはセッションで設定した最低選択数〜最大選択数の選択が必要です。「保存中」「保存済み」「未保存」「再接続中」を回答欄の上に表示し、保存に失敗した場合はこのタブ内で入力を保持して再試行します。理由・エピソードは各1000文字以内です。自己評価の記述は本人の結果だけに表示し、他者評価の記述は特徴ごとに匿名でまとめます。JSON・CSV・印刷にも含まれます。未保存の入力がある状態で再読み込み・タブを閉じる操作をすると、ブラウザが確認を表示します（ブラウザによって表示されない場合があります）。保存済み表示を確認してください。タブを開いたままの一時的な通信切断では、Socket.IOの再接続と15秒間隔の状態確認で進行を復元します。再読み込み・タブを閉じる操作では認証情報も失われるため、同じ回に戻るには参加キーが必要です。

## ホスト1人で試す（デバッグ）

入り口の「一人で試す（デバッグ）」を押すと、サンプル参加者2人を含む専用ルームを作ります。表示名は省略できます。「デバッグを開始」から自分の特徴を選び、理由・エピソードを任意で入力します。サンプル参加者も設定した選択数で自動回答するので、続けて2人への他者評価を入力すれば、結果の公開・メモ・エクスポートまで一人で操作できます。

通常の2〜10人用ルームとは独立しています。デバッグルームへの新規参加はできず、途中から通常の診断への切り替えもありません。画面・印刷・エクスポートにデバッグであることを記録します。データは通常と同様にメモリ内だけで扱い、サーバー停止で消えます。

## 一時保存・同じ回に戻る

セッション・参加者・回答・結果・振り返りメモは、ホストPCで動作するNode.jsプロセスのメモリだけに保持します。データベースやデータファイルは作成しません。サーバーを停止・再起動するとすべて消え、参加キーでも復元できません。ブラウザを閉じるだけではサーバーは停止しません。

認証トークンや履歴もlocalStorage・sessionStorage・Cookieへ書き込みません。同じタブ内の切り替えに使う参加履歴だけをメモリに保持します。再読み込みする前に、画面上部の一時セッション案内にある「同じ回に戻るための参加キー」を本人だけで控えてください。サーバーの起動中に限り、入り口の「同じ回の回答・結果に戻る」からキーを入力して再開できます。キーがない場合は本人として戻れません。

以前のバージョンのSQLiteファイルを自動的に読み込む機能は廃止しました。旧DBが別のPCやバックアップに残っている場合は、サーバー停止後に旧data/johari.sqliteと同名の-wal・-shmファイルを利用者が削除してください。旧ブラウザ履歴のjohari-current・johari-historyは、新しい画面を開いた際に削除します。古い画面を開いたままのタブは再読み込みするか閉じてください。

APIと画面の応答にはCache-Control: no-storeを付けています。これはアプリによる自動保存を避ける方式であり、OSのスワップ・クラッシュダンプやブラウザ独自の保存など、端末全体の痕跡を完全消去する保証ではありません。利用者が保存したJSON・CSV・PDF、スクリーンショット、コピーした参加キーは自動削除しません。

## LAN接続の確認

- Windowsのファイアウォールでは信頼する**プライベートネットワーク**に限りNode.jsまたはTCP 3000の受信を許可してください。
- macOSでもファイアウォールが尋ねた場合にNode.jsの着信を許可してください。
- ゲストWi-Fiや公共Wi-Fiでは「AP isolation」「端末間通信禁止」により接続できない場合があります。端末間通信を許可した信頼できるネットワークを使用してください。
- 接続できない場合はWindowsの `ipconfig`、macOSのネットワーク設定でWi-FiのIPv4アドレスを確認し、`http://そのIP:3000` を開いてください。
- ルーターのポート開放やインターネットへの公開は行わないでください。

## プライバシーと判定

結果APIは公開後の認証済み本人だけに応答します。ホストも他人の回答本文を取得できません。状態APIに含むのは全員の完了状況と本人の保存済み回答です。ソケットは認証済みルームへ更新通知だけを配信します。認証トークンは暗号学的乱数で発行し、サーバーのメモリにはハッシュだけを保持します。本人向けエクスポートに回答者IDは含めません。CSVでは数式として解釈され得る先頭文字を無害化します。回答本文をログへ出力しません。

画面上は匿名ですが、少人数では文章から回答者が推測されることがあります。稼働中のサーバーのメモリは管理者がアクセスできるため、ホストPC管理者に対する完全な匿名性はありません。**ローカルHTTPは暗号化されません**。Wi-Fiを信頼できること、PCへのアクセスを管理することが利用条件です。復元キーを他人に渡さないでください。ルームコードとURLも参加者だけに共有してください。結果共有は本人の判断で行ってください。

他者認識の基準は「評価者の過半数」です。2人での診断では評価者1人の選択で判定します。評価者2人なら2人、3人なら2人、4人なら3人、9人なら5人の選択が必要です。双方が選択しない項目は「未選択」であり「未知」ではありません。結果画面とエクスポートには、自分または他者が1人でも選んだ特徴だけを表示します。自分が選ばず、他者が選んでも過半数に届かない項目は「一部の他者が選択」と表示します。同数の場合も含め、「一部の人が選んだ特徴」欄に人数付きで表示します。自分が選んだ場合の分類は「秘密」を維持し、他者の一部も選んだことを併記します。未知の窓は説明用領域として表示します。

## テスト

```sh
npm test
npm run build
```

集計の過半数・同数境界、入力検証、本人限定の公開条件、2人・3人・10人のAPIフロー、1人での開始拒否・11人目の入室拒否、権限エラー、開始後入室禁止、結果エクスポート用データからの内部ID除外、メモの一時保存、ファイルが作られないこと、再起動でアクセス不能になることを確認します。統合テストは一時ディレクトリと31987〜31989・31992〜31995・32000番ポートを使います。

MVPの範囲として、ホスト交代・参加者の削除・確定後編集・パスワード回復・TLSの自動設定・自動バックアップは含みません。スマートフォン実機の接続とmacOS実機での動作は、それぞれの環境で確認してください。
